# 🚀 Overview

**LOGIMIND** is an AI-powered operations intelligence platform built specifically for distributors.

Traditional logistics dashboards primarily answer:

> **"What is happening?"**

LOGIMIND goes further by answering:

> **"Why is it happening, what happened before, and what should we do now?"**

The platform analyzes current operational data, identifies geographical and operational patterns, retrieves relevant historical experiences using **Hindsight long-term memory**, and uses an LLM to generate context-aware operational recommendations.

The system continuously learns from operational outcomes, creating a feedback loop where previous decisions influence future recommendations.

---

# 🎯 Problem

Distributors manage large amounts of operational information every day:

- 📦 Shipments
- 🚚 Delivery agents
- ⏱️ Delivery delays
- ❌ Failed deliveries
- 🗺️ Geographical hotspots
- 📊 Agent workloads
- 📅 Peak delivery periods
- 📈 Historical performance

Traditional dashboards provide metrics and charts, but they often lack **operational context and memory**.

For example:

> Area C has experienced repeated delivery delays during evening hours.

A normal dashboard may show the delay.

But the important questions are:

- Has this happened before?
- What caused it?
- What action was taken previously?
- Did that action work?
- What should the distributor do now?

LOGIMIND is designed to answer these questions.

---

# 💡 Solution

LOGIMIND acts as an **AI Operations Analyst** for distributors.

It combines:

```text
Current Operational Data
          +
Historical Operational Experiences
          +
LLM Reasoning
          ↓
Context-Aware Recommendation
```

The system doesn't treat every operational problem as a completely new problem.

Instead, it can retrieve relevant experiences from its long-term memory and use them when generating recommendations.

# 🧠 Hindsight Long-Term Memory

One of LOGIMIND's main differentiators is its use of **Hindsight** as genuine long-term operational memory.

Hindsight allows LOGIMIND to retain and recall operational experiences across different days and incidents.

### Memory Flow

```text
Operational Event
       ↓
Decision
       ↓
Action
       ↓
Outcome
       ↓
Hindsight RETAIN
```

Later:

```text
New Operational Problem
       ↓
Hindsight RECALL
       ↓
Relevant Historical Experience
       ↓
LLM Reasoning
       ↓
New Recommendation
```

This gives LOGIMIND the ability to use **organizational experience**, rather than treating each incident independently.

## 1. Clone the Repository

```bash
git clone <YOUR_REPOSITORY_URL>

```

---

# 🔧 Backend Setup

```bash
cd backend
```

Create a virtual environment:

```bash
python -m venv venv
```

Activate it.

### Windows

```bash
venv\Scripts\activate
```

### Linux / macOS

```bash
source venv/bin/activate
```

Install dependencies:

```bash
pip install -r requirements.txt
```

Create:

```text
backend/.env
```

Add the required environment variables.

Start the backend:

```bash
uvicorn main:app --reload
```

Backend will run on:

```text
http://localhost:8000
```

API documentation:

```text
http://localhost:8000/docs
```

---

# 💻 Frontend Setup

Open another terminal:

```bash
cd frontend
```

Install dependencies:

```bash
npm install
```

Start the development server:

```bash
npm run dev
```

Frontend will run on:

```text
http://localhost:5173
```

# 🔐 Environment Variables

Create a `.env` file inside `backend/`.

```env
MONGO_URI=
DATABASE_NAME=logimind

HINDSIGHT_API_URL=
HINDSIGHT_API_KEY=
HINDSIGHT_BANK_ID=logimind-distributor-hub-01

LLM_PROVIDER=groq
LLM_API_KEY=
LLM_MODEL=llama-3.3-70b-versatile

FRONTEND_URL=http://localhost:5173
```

> **Never commit `.env` files or API keys to GitHub.**
